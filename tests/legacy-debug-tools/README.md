# Running Tests

This repository includes several scripts and tools to set up, run and debug test scenarios
using docker containers or just plain Linux network namespaces.

## Building Container Images

To build the relevant container images, use the Makefile provided in the root directory. To build all images, run:

```sh
make build-images
```

## Running Tests

Simple test scenarios can be set up with the test scripts provided here in the [tests](/tests/) directory.
These scripts require a GML file that describes the network topology and the container images:

```sh
python3 tests/legacy-debug-tools/test.py tests/topos/minimal.gml
```

For additional features and a Containernet CLI use [tests/test2.py](/tests/test2.py)
This will set up environment variables in the containers for debugging purposes, dump an `idmap.json` file for easier collection and processing of logs from the containers and provide a Containernet CLI:

```sh
python3 tests/legacy-debug-tools/test2.py tests/topos/minimal.gml
```

## Collecting and Processing Logs

After running the tests, the logs from all containers can be collected using:

```sh
python3 tests/legacy-debug-tools/logs.py
```

This script also replaces all `node_ids` and their representations as IPv6 addresses with the node numbers for better readability.

## Further Debugging Options

To attach to any running container for further debugging, use the `docker exec` command.
The containers are named `mn.k*`, where `*` is the node number.
For example, to get an interactive shell in node 1, run:

```sh
docker exec -it mn.k1 bash
```

#### Environment Variables

When using the [tests/test2.py](tests/legacy-debug-tools/test2.py) script, every container has environment variables set like `$n*` to make it easier to interact with other nodes. For example, use the `ping` command to further debug connectivity issues:

```sh
ping $n1
```

#### Observing Traffic

Traffic generated by using `ping` can conveniently be observed on any given node by using the [tests/dump.sh](/tests/dump.sh) script:

```sh
./dump.sh mn.k2
```

#### Viewing Forwarding Information

To view the forwarding and decapsulation rules installed by the kira daemon, run the following command inside a container:

```sh
nft list ruleset
```

#### Viewing Routing Information

To view the IPv6 routing table, use the `ip -6 route` command inside a container. The output contains all encapsulation routes, routes to underlay neighbors as well as via routes which map installed paths to the correct next hop address and interface.

```sh
ip -6 route
```

To get the route to a specific node, use the `ip route get` command:

```sh
ip route get $n2
```

# Demo Topology

In this folder are tools to automatically construct and manage topologies.

All tools can use the provided docker images of the routing daemon
which can be found in [`../docker`](../docker).

To get an overview of the arguments required and optional simply run `demo.py --help` 

The main operations are:

1. `create`: Create docker containers (can be skipped)
2. `connect`: Connect the docker containers
3. `start`: Start all containers
4. `stop`: Stop all containers

## Backends 

There are two backends supported to create the networks.

### Containernet

This backend uses [Containernet](https://containernet.github.io) to build the topology.
To use this backend you need to specify `--containernet` as command-line-argument.

This backend creates, connects and starts the network all in the `start` step.
It is not possible to only "create" the network without connecting it.
Use the docker backend if you want to do so.

#### Dependencies

- installed [Containernet](https://containernet.github.io/#installation)
- pip modules: `pip install docker networkx`
- routing daemon docker image (use `make build-images`)

## Standalone 

This backend does not need any external dependencies apart from docker to run.
In contrast to the Containernet backend, this backend uses vanilla docker
bridge interfaces to bridge the nodes.

#### Dependencies

- [docker](https://www.docker.com/)
- pip modules: `pip install docker networkx`
- routing daemon docker image (use `make build-images`)

#### Docker Setup requirements

> This setup doesn't seem to be required anymore for newer docker versions and can be skipped.

Since the kirad requires IPv6 support you must [enable support for IPv6 in docker](https://docs.docker.com/config/daemon/ipv6/) first:

Edit `/etc/docker/daemon.json` to at least include `default-address-pools` for IPv6 and `ipv6tables`:

```json
{
    "experimental": true,
    "ip6tables": true,
    "default-address-pools": [
        { "base": "172.17.0.0/12", "size": 20 },
        { "base": "192.168.0.0/16", "size": 24 },
        { "base": "2001:db8::/104", "size": 112 }
    ]
}
```

This is sadly required since it wasn't possible to automatically obtain
link-local IPv6-addresses without also obtaining a global unicast address.

Keep in mind that `2001:db8/32` addresses are only intended to be used in 
internal examples and documentations by the IANA, which is OK here,
since we don't use them anyway.

Afterwards restart docker with `systemctl restart docker.service`.
